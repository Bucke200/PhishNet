# Evaluation waivers

A waiver here means exactly one thing: the frozen CSVs are the measurement
instruments, pinned by sha256 and usable read-only indefinitely, but they
can never be regenerated byte-for-byte from the repository. Nothing waived
may be rebuilt, edited, or "fixed" in place; each entry records what was
proven, what still reproduces exactly, and where the blast radius ends.

Both waivers below share one root cause. It is stated once, precisely, in
Waiver 2 (the entry where the investigation corrected an earlier,
wrong diagnosis).

## Waiver 1 — Phase 1 (`data/splits/`, `reports/baseline.json`)

- **Status:** waived, frozen, hash-pinned (`test.csv` sha256
  `385aa409c222247f04255f760fa3e86ee9e38d3d6d08b1d410ff57f6780b49fb`).
- **What reproduces:** determinism (repeated rebuilds byte-identical),
  counts, benign partitioning mechanism, audit verdict band.
- **What does not:** byte-exact rebuild. 84 test URLs carry a `first_seen`
  of `2026-09-12 13:29:21` that exists nowhere in the committed raw inputs
  (the committed `openphish-2026-09-12.jsonl` carries a single stamp,
  `13:06:02`). The split was built from a same-day re-fetch of the live
  OpenPhish feed that was never committed; `collect.py` names snapshots by
  date, so the two fetches are indistinguishable by filename.
- **Blast radius:** phish-side `first_seen` values and URL-set/cap-sample
  churn only. The frozen bytes themselves are stable, hash-verified on
  every checkout (golden tests), and fully characterized (overlap 0,
  temporal purity exact, audit an exact function of the CSVs).

## Waiver 2 — Phase 2 enlarged (`data/splits-large/`, `reports/phase2-*.json`)

- **Status:** waived, frozen, hash-pinned (`test.csv` sha256
  `961efe5c9bfc95495446223e92d9ddfb50bf85c4888a7fa6ac83cb510260c379`).
- **Corrected root cause (supersedes the PSL-drift diagnosis):** PSL drift
  was investigated and ruled out as the differentiator. A rebuild with the
  extractor pinned to the bundled snapshot produces **byte-identical**
  output to a rebuild with the live PSL (`db29b8be…` both), and the benign
  side reproduces exactly: train URL sets 18464/18464 with zero diff,
  test domains 371/371 with zero diff, test benign count 1668 exact.
  The residual is the same defect as Waiver 1: the committed test CSV's
  openphish rows carry `13:29:21` while the committed openphish file says
  `13:06:02` — the build-time snapshot is gone. The large benign-test URL
  churn on top (~931 swapped picks over identical domains) rides on the
  seeded global-shuffle campaign cap: one shuffle over the whole test
  frame, so phish-side input churn reorders benign picks. Deterministic,
  but churn-amplifying by design.
- **Blast radius:** phish-side only. Benign partitioning reproduces
  exactly, so every benign-side measurement on the frozen bytes stands as
  recorded.

## Recurrence fixes (landed with the waivers)

- `collect.py` refuses to write a snapshot file that already has content
  (explicit `--clobber` required), so a same-day re-fetch can never again
  silently replace or merge into a committed snapshot's bytes.
- `build_splits.py` records `raw_file_hashes` (sha256 per input file) in
  every new manifest, so swapped inputs are visible at build time.
- The PSL is pinned to the bundled snapshot (`psl_snapshot_sha256` in new
  manifests; socket-blocking golden fixture; shared-suffix grouping table),
  closing the drift vector for all future populations.
- The successor population (`data/splits-eval/`) is not waived: it
  rebuilds byte-exactly from committed inputs and is hash-pinned in
  `repro/hashes.json`.

## Known PSL-vintage note (informational, not a waiver)

- The frozen `data/splits` and `data/splits-large` train files store the
  same 2 URLs as `arweave.io.vn` (live-PSL grouping at build time); the
  pinned snapshot groups those hosts as `io.vn`. Both rows are train-only
  under either grouping, so eTLD+1 overlap is 0 both ways. Frozen bytes
  are intentionally untouched; URL-recomputed audits are the source of
  truth.
